# Сборка в один `.exe`

Спецификация `build_exe.spec` реально протестирована в этом проекте (сборка
Linux-бинарника через тот же PyInstaller, тот же spec-файл, тот же код) —
проверено: упаковка ресурсов (`schema.sql`, `kit-templates.json`, `public/`),
разрешение путей, чтение конфига, автобэкап при старте, приём сканов через
HTTP, и отдельно — поведение при битом `kit-templates.json` (чистое
сообщение об ошибке, exit code 1, без создания мусора в БД). Сам `.exe` для
Windows нужно собрать на Windows-машине — PyInstaller не кросс-компилирует
между ОС, а компилирует только "под себя".

## Что нужно на машине для сборки

- Windows 10/11 (та же ОС, на которой будет работать сервер — PyInstaller
  собирает бинарник только под свою текущую ОС/архитектуру)
- Python 3.11+ (скачать с python.org, при установке отметить "Add to PATH")
- Доступ в интернет на время сборки (разово, для `pip install`)

## Шаги

```powershell
cd km-tracker-py
python -m venv venv
venv\Scripts\activate
pip install -r requirements.txt
pip install pyinstaller

pyinstaller build_exe.spec --noconfirm
```

Результат: `dist\km-server.exe` — один файл, ничего больше не нужно
устанавливать на сервере (сам Python внутри этого экземпляра не нужен —
интерпретатор и все зависимости уже вшиты в exe).

## Проверка после сборки

```powershell
cd dist
km-server.exe
```

В консоли должно появиться:

```
КМ-сервер запускается...
  На этом компьютере:  http://localhost:8000
  С других станций в сети:  http://<реальный IP>:8000
```

Откройте `http://localhost:8000` в браузере — должен открыться интерфейс.
Рядом с `km-server.exe` появится папка `data/` — это нормально, туда пишется
БД и бэкапы.

## Перенос на серверный ПК склада

Скопируйте **только** `dist\km-server.exe` на целевой компьютер (папку
`data/` создавать не нужно — появится сама при первом запуске). Ничего
дополнительно устанавливать не требуется — ни Python, ни какие-либо
библиотеки, exe самодостаточен.

Если нужно донастроить справочник наборов под реальные КМ клиента —
редактируйте `app/config/kit-templates.json` **в исходниках** и пересоберите
exe заново (после сборки файл уже "зашит" внутрь и не редактируется отдельно).
Альтернатива, если пересборка неудобна: держите `km-server.exe` и заменяйте
только сам процесс правки/пересборки на машине разработчика, а на склад
переносите готовый файл.

## Частые проблемы при сборке (уже учтены в `build_exe.spec`, но если что-то поменяется)

- **`ModuleNotFoundError: pydantic_core` при старте exe** — pydantic v2
  использует скомпилированное Rust-ядро, PyInstaller не всегда находит его
  автоматически. В spec-файле это решено через `collect_all('pydantic')` /
  `collect_all('pydantic_core')` — если после обновления версий FastAPI/pydantic
  ошибка вернётся, добавьте `collect_all` для новых подпакетов по этому же образцу.
- **`ImportError` вокруг uvicorn при старте** — uvicorn выбирает реализацию
  event loop/протокола по строке, не прямым `import`, поэтому PyInstaller не
  видит эти модули статически. Уже перечислены в `hiddenimports` spec-файла
  (`uvicorn.loops.auto`, `uvicorn.protocols.http.auto` и т.д.).
- **Антивирус ругается на exe** — типично для PyInstaller-сборок (ложное
  срабатывание из-за самораспаковывающегося формата). В spec-файле `upx=False`
  специально, чтобы не усугублять — UPX-сжатие ещё чаще триггерит антивирусы.
  Если всё равно ругается — добавьте exe в исключения антивируса на серверном ПК
  или подпишите бинарник корпоративным сертификатом, если он есть.
- **Windows Defender SmartScreen блокирует первый запуск** — нормально для
  неподписанного exe. "Дополнительно" → "Выполнить в любом случае".

## Автозапуск на сервере склада

Простое решение — ярлык на `km-server.exe` в папке автозагрузки Windows
(`shell:startup`). Более надёжное — через Планировщик заданий Windows с
триггером "при входе в систему" и настройкой "перезапускать при сбое".
